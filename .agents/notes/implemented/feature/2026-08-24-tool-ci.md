# Feature: tool-ci (CI quality-gate tool)

## Status

Implemented

## Summary

Adds @deepseek-ai/dsh-tool-ci, a model-facing `ci_run` tool that runs one or more CI quality-gate commands (lint, typecheck, test, build, and so on) in sequence in a target directory over the `ctx.shell` capability seam, returning a structured `{ cwd, overall, gates[] }` verdict. The tool owns model-facing concerns only: schema, prompt section, per-gate validation, bounded output projection, and terminal presentation.

## Motivation

Previously each gate was a separate bash call, and the model had to infer the overall verdict from interleaved output. `ci_run` gives a single structured result and a first-failure stopping policy.

## Behavior

- Each gate is a shell command string; the tool runs them in order, capping the captured stdout/stderr tail per gate.
- A non-zero exit, a terminating signal, an executor timeout, or an abort marks the gate failed; by default the sequence stops at the first failure and marks the rest skipped.
- The canonical value is the programmatic API; the Native renderer folds it into a markdown summary. The terminal card (presentCall/presentResult) carries the combined output for the UI.
- Config: timeoutMs (per-gate budget), maxOutputChars (output cap), stopOnFailure (default policy).

## Wiring

tool-ci is registered in the base bundle (packages/bundle/base/cordis.patch.yml) for CLI profiles and in the standard agent preset (apps/cli/config/agent-presets/standard/agent.cordis.yml) for the Web surface, plus the corresponding package dependency in packages/bundle/base/package.json.
